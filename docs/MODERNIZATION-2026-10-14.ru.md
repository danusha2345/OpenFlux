# Модернизация OpenFlux — 14.10.2026

## Основа

Исходный проект: https://github.com/p1neappleXpress/OpenFlux.
Для интеграции выбран релиз `v0.7.3` (`f12e9816`), а не плавающий `main`.
Desktop/Android основаны на релизах `v2.6.3` соответствующих upstream-репозиториев;
общий Compose-модуль закреплён на `1259fe0a`.

Свежий апстрим добавляет Session, TCP/UDP, HTTP-прокси, Windows Wintun,
Telemost/Avito/Boards, несколько транспортов, восстановление и ARQ, мастера
установки ноды, общий UI Android/Desktop. Исправлены размер cursor Яндекса,
заголовки и сжатие WebSocket Mail.ru, ограничения скорости batching и буферов L4.

Наши изменения поверх апстрима:

- Возвращён запрет приватных/link-local назначений exit-ноды для TCP и UDP;
  доступ разрешается только явным `--allow-private`. SOCKS5 по умолчанию
  слушает `127.0.0.1`, а не все интерфейсы.
- DNS имён приложений проходит TCP-запросом через туннель к `1.1.1.1:53`.
  Это исключает подстановку локальным VPN fake IP `198.18.x.x` и локальную
  утечку DNS. Литералы IP не требуют DNS, IPv6 пока не поддерживается.
- В тесте Cups устранена гонка проверки счётчика: доставка у фейкового сервера
  может завершиться до возврата WriteMessage и учёта отправленного пакета.
- Desktop собирается для Linux с runtime Java; Windows portable использует
  проверенные upstream GUI/runtime 2.6.3, наше пересобранное ядро и версию
  пакета 2.6.4. NSIS installer собирается локально; удаляет только установленные
  файлы, сохраняя профили. GUI-классы Windows не компилировались на Linux заново.
- Android 2.6.4 собирается из исходников с нашим AAR, подписан прежним
  сертификатом проекта. Обновления направлены в наш GitHub fork.

## Новый сервер

- Адрес: `<VPS_ADDRESS>`; SSH alias задаётся локально.
- Unit: `openflux-modern.service`; непривилегированный пользователь `openflux`.
- Binary: `/opt/openflux/openflux`; конфигурация `/etc/openflux/openflux.conf`.
- Секрет: `/etc/openflux/session.key`, в Git и публичных релизах отсутствует.
- Состояние/cookies: `/var/lib/openflux`; прямой канал TCP `<DIRECT_PORT>`.
- Backend L4; никаких глобальных iptables-правил; лимиты 512 MiB и 75% CPU.
- Предыдущая нода не изменена.

## Несовместимость и профили

Старые Noise-профили `openflux://noise-v1/` несовместимы с новым Session/AES-GCM.
Нужны новые `openflux://v1/` ссылки, содержащие общий секрет. Они передаются
пользователю отдельно; не публиковать их в issues/релизах/скриншотах.
Android использует пакет `io.openflux.client` и устанавливается рядом со старым
`io.github.p1neapplexpress.openflux`; старые профили автоматически не переносятся.

Для Avito и Cups комнаты создаются при подготовке ноды, затем их коды сохраняются
в конфигурации. После рестарта коды не меняются. Ссылка на объявление Avito не нужна.
Основной профиль содержит Avito, Cups и резервный Direct. Одна Session обслуживает
один активный клиент: параллельные устройства должны иметь отдельные сессии/ноды.

## Проверка и границы

- Проверяются `go test -race ./...`, `go vet ./...`, Compose JVM tests,
  Android unit tests, подпись и package/version APK, совпадение всех четырёх
  native .so в APK с собранным AAR, SHA-256 Windows portable и встроенного ядра.
- На новом сервере независимо проверен HTTPS 200 через Avito, Cups и Direct.
  После изменения DNS проверяется также HTTPS по доменному имени.
- Linux GUI запускается в отдельном Xvfb; проверены импорт профиля и реальный
  SOCKS5 запрос с выходным IP новой ноды. Системный proxy хоста не менялся.
- Физический Android не подключён. Полноценной Windows-машины нет; локальный
  Wine установлен без 64-битного runtime и не заменяет Windows acceptance.
  Windows VPN/Wintun и установка APK требуют проверки пользователем.
- Сохранённые Яндекс/Volga ссылки сейчас возвращают страницу без editor config,
  Mail.ru — HTTP 400. Их не считать рабочими и не включать в основной профиль.
  Это отдельная проверка доступа/редактора, не доказательство отказа всего сервиса.

## Выпуск

Публичные релизы не содержат секретов или личных профилей. В форках автоматическая
публикация по tag отключена: CI тестирует код, а проверенные локальные артефакты
публикуются одинаковыми на GitHub/GitLab/Forgejo. Upstream workflow Release остаётся
доступен вручную. Перед пересборкой клиентов выполнить `scripts/sync-core.sh`.
