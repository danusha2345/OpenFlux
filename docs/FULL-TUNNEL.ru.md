# Защита полного туннеля

Режим SOCKS5 / системного прокси обслуживает только программы, использующие
прокси. Он не защищает прямые соединения, WebRTC или весь UDP компьютера.
Для защиты адреса устройства выбирайте «Весь трафик компьютера (TUN)».
IPv6 через exit пока не поддерживается и блокируется в полном туннеле.

Windows использует Wintun и динамические фильтры WFP из библиотеки WireGuard.
Фильтры разрешают интерфейс туннеля, localhost и служебные соединения ядра;
прямые соединения других программ блокируются. Ошибки настройки IPv6, DNS,
маршрутов или WFP останавливают запуск. При завершении процесса Windows
автоматически удаляет фильтры WFP.

Linux требует root для ядра, `ip`, `nft`, `resolvectl` и работающий
systemd-resolved. GUI запрашивает права через `pkexec`, оставаясь обычным
пользовательским процессом. Правила находятся в отдельной таблице nftables;
разрешены localhost, маркированные соединения ядра и IPv4 через TUN.
DNS задаётся только для интерфейса TUN. При остановке интерфейс, его маршруты
и правила удаляются. Отдельный процесс удаляет таблицу и при аварийном
завершении ядра; чужие правила и основной маршрут не изменяются.

Состояние «Подключено» выдаётся после успешной настройки защиты и маршрутов.
При потере связи с exit правила продолжают блокировать обход туннеля, пока
пользователь не остановит подключение.

Проверки разработки: Go race-тесты, vet, кросс-сборка Windows и тест отката
при ошибке маршрута IPv6 с подменёнными сетевыми командами. Эти проверки
не заменяют проверку внешнего IP, DNS и WebRTC на Windows и Linux с реально
включённым TUN. Текущий VPN рабочей станции во время разработки не переключался.

## Проверка Windows без включения туннеля

`openflux-windows-amd64.exe --check-windows-tun` проверяет идентификацию
процесса для WFP и открытие сессии WFP. Фильтры и маршруты не добавляются.
Это помогает отличить ошибку прав/Windows от проблем транспорта, но не
заменяет запуск Wintun и проверку утечки с включённым туннелем.

GUI уже поддерживает отдельное ядро: в настройках ядра выберите собственный
путь к EXE. Для TUN файл wintun.dll должен лежать рядом с этим EXE. Поэтому
для исправления ядра не требуется переустанавливать или пересобирать GUI.
