# Обновление OpenFlux — 30.10.2026

## Основа и сохранённые изменения

Ядро: upstream `v0.17.1` (`f492a1a33b7581ad8f88118f97e0b866adda3cdc`),
клиенты: Desktop/Android `v3.7.0`, общий модуль
`7d8c56f46ed57d808159634e1830d255c21cf409`. Выпуск форка:
`0.17.1-danik.1` для ядра и `3.7.1` для клиентов.

Интеграция сохраняет историю обеих веток. За основу дерева взят релизный тег,
поверх перенесена разница нашего форка относительно `v0.7.3`.
`main` upstream не является свежим релизом; тег совпадает с nightly.

Сохранены `--allow-private`, loopback SOCKS5 по умолчанию, DNS приложений
через туннель, WFP Windows, nftables Linux и выдача Connected только после
настройки полного туннеля. В Linux TUN добавлены upstream ClampDeviceSyn и
SendFromDevice: малый MTU транспорта больше не обходится отдельным Linux-путём.

## Ревью

Проверена интеграционная разница, перенос защит форка и изменения в критических
путях: Session/KDF, framing/batching и владение буферами, MTU и TCP segmentation,
Direct takeover, stripe-группы, Avito backoff, Mail.ru cookies, Yandex engine.io,
script setup/signatures/WebRTC pacing, subscription TLS/auth/provisioning,
клиентские вызовы mobile API и запуск привилегированного ядра.
Автоматические проверки охватывают все Go-пакеты; ручное ревью сосредоточено
на перечисленных путях, а не является обещанием отсутствия всех дефектов.

Скопированный `pion/sctp v1.11.3` сравнен с модулем-оригиналом: среди Go-файлов
отличается только `association.go`, добавляющий проверяемый atomic MTU override.
Лицензия и описание патча сохранены.

Исправления по результатам проверки:

- Avito: ERR_ROOM_NOT_FOUND при записи в существующий ShareDB-документ
  тоже запускает Socket.IO rejoin; ранее восстановление работало только при create.
- MAX: ошибки Connect/Login больше не игнорируются; вызов без соединения
  возвращает ошибку вместо nil-pointer panic. Добавлен регрессионный тест.
- Avito: предсказуемый временный файл gate заменён на CreateTemp с `0600`.
  Тест проверяет сохранность цели заранее подставленного symlink.
- Android переведён с PendingCaptcha/SubmitCaptcha/CancelCaptcha на новый
  PendingPrompt/SubmitPrompt/CancelPrompt API.
- Мобильные тесты обновлены под закреплённый KDF-контекст; тест совместимости
  с прежним контекстом сохранён. Локальные exit-fixtures явно разрешают private
  адреса только на время теста; рабочий запрет не ослаблен.
- Два нестабильных upstream-теста исправлены: ожидание асинхронного provisioning
  и измерение pacing на стороне отправителя вместо времени пробуждения receiver.
- Go закреплён на `1.26.10`; x/net обновлён до `0.60.0` с согласованными
  x/crypto/x/text. Глобальный Go не менялся.

## Проверки

- `go test -race ./...` и `go vet ./...` в корне и отдельном модуле `mobile`.
- `govulncheck v1.9.0`: 0 уязвимостей импортируемых пакетов/вызываемого кода;
  три записи остаются в требуемых модулях без обнаруженного пути вызова.
- Desktop: `:shared:jvmTest`, `:desktopApp:test`, Linux createDistributable.
- Android: gomobile AAR для четырёх ABI, release APK с прежним сертификатом;
  запрошенные Android unit-test tasks имеют NO-SOURCE — это не выполненные тесты.
- Windows: кросс-сборка ядра; GUI jars пересобираются на Linux и помещаются
  в проверенный upstream Windows runtime 3.7.0. Это не Windows acceptance.

При первой проверке с длинным GOTMPDIR превысился лимит AF_UNIX path;
повторный набор с обычным временным каталогом проходит. Параллельная нагрузка
выявила два исправленных теста времени; проблемы не скрыты исключением tests.

## Сервер и профили

Цель: SSH alias `tgbots`, unit `openflux-modern.service`, binary
`/opt/openflux/openflux`, config `/etc/openflux/openflux.conf`.
Ключ и явный SessionContext сохраняются. Сервис подписок и PHP exit не включаются.

До развёртывания HTTPS через Direct новым клиентом к старой ноде подтверждён.
Cups с сервера возвращает 404 для прежних комнат — они удалены внешним сервисом;
нужны новые комнаты и обновлённый профиль. На клиентском хосте также наблюдается
TLS EOF к cups.online. Avito до обновления отвечает 429, на старой ноде нет
нового общего backoff. Эти наблюдения не являются результатом нового deploy.

Развёртывание: сохранить binary/config/unit/state в закрытом каталоге backup,
проверить SHA-256 загруженного binary, заменить атомарно и перезапустить unit.
При отказе Direct восстановить binary и config из backup и перезапустить.
Итог runtime и ссылки выпуска фиксируются после проверки.

Физический Android, Windows Wintun/DNS/WebRTC и macOS в этой среде не проверяются.
Личные профили, ключи, cookies и закрытые журналы не входят в Git/релизы.

## Результат развёртывания и клиентские проверки

Сервер обновлён с backup `/opt/openflux/upgrade-20261030/backup`.
После обновления подтверждены HTTPS 200 по Direct и новым комнатам Cups
клиентом, запущенным на сервере; удалённые комнаты не подменены предположением.
С рабочей станции Direct тоже проверен; её TLS EOF к cups.online остаётся
ограничением внешнего пути. Для нового Cups создан закрытый профиль импорта.
Avito также подтверждён отдельным HTTPS 200 с клиентом, у которого настроен
только Avito (без Direct fallback). Старые комнаты заменены одной новой парой;
это уменьшает число стартовых подключений. При проверке через combined-profile
Direct остаётся предпочтительным, поэтому такой probe не доказывает Avito.

Desktop: 676 shared JVM tests и 9 desktop tests — 0 failures/errors/skips.
Linux GUI: изолированный Xvfb, окно открывается, второй запуск активирует
существующий экземпляр. Профили и VPN рабочей станции не переключались.
Android lint обновлён до 9.5.0 (lint engine 32.5.0); атрибут navigation bar
перенесён в API 27 resource variants. Старый tile Intent API оставлен только
под SDK <34 с объяснённым подавлением проверки; новая ветка использует PendingIntent.
Полный lintRelease проходит; остаются предупреждения upstream и Gradle deprecation.
Проверены package `io.openflux.client`, versionCode `30701`, versionName `3.7.1`,
совпадение четырёх .so в universal APK с финальным AAR и прежний сертификат подписи.
