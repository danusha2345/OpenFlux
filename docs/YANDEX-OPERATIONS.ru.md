# Яндекс: эксплуатация и проверка от 19.09.2026

## Настройки

На клиенте выбрать `yandex` (Yandex Docs), не `vyandex` (Volga).
Клиент и выходная нода используют одну ссылку на документ, кодек `batched`
и Noise. В поле Peer key клиента передаётся публичный ключ выходной ноды.
Рабочие ссылки и ключи распространяются отдельно, в репозиторий не включаются.

Одной настройки телефона недостаточно: сервер должен быть запущен с тем же
транспортом и документом. Сообщение приложения о подключении следует сверять
с передачей данных; один WebSocket ещё не подтверждает Noise-сессию.

## Сервер

Постоянная служба Яндекса — `openflux-yandex.service`, режим выхода `l4`.
Включены автозапуск и `Restart=on-failure`. Служба использует
`/opt/openflux/openflux-test-latest` и `/opt/openflux/exit.key`.
Mail.ru продолжает работать отдельной службой `openflux-exit.service`.
Ранее использовавшаяся временная `openflux-yandex-test.service` остановлена.

Команды на сервере:

```sh
systemctl status openflux-yandex.service
journalctl -u openflux-yandex.service --since '10 minutes ago' --no-pager
systemctl show openflux-yandex.service -p MainPID -p ActiveState -p NRestarts
ss -tinp
```

Обычный журнал без debug не содержит подробностей каждого рукопожатия.
Для диагностики дополнительно проверять сокеты нужного PID и счётчики байтов.
Не публиковать полные командные строки и журналы без маскировки ссылок и секретов.

## Что проверено

- Яндекс вернул конфигурацию документа, WebSocket подключился.
- Локальный клиент установил Noise-сессию с сервером; HTTPS через SOCKS
  к `example.com` вернул HTTP 200. Повторный тест после постоянного запуска
  также прошёл: счётчики выросли до `tx=2317`, `rx=5490`.
- После сообщения пользователя о подключении телефона у процесса Яндекс-ноды
  появились новые исходящие TCP-соединения с отправленными и полученными байтами.
  Это серверное подтверждение обмена, не отдельная проверка загрузки страниц на телефоне.
- Длительная устойчивость, восстановление после сна и смены сети этим тестом
  не проверены. Успешный запуск не закрывает все пункты ревью транспорта.

## Остаток работ

- Проверить восстановление Android при смене Wi-Fi/мобильной сети, сне и обрыве
  документа; сверить счётчики приложения с реальным обменом.
- Volga: переавторизация при ошибке WS уже есть, но HTTP relay при не-200/204
  возвращает общую ошибку; нужен отдельный сценарий обновления при 401/403
  и тест истечения токена.
- L3: проверить и устранить коллизии портов с соединениями хоста; текущий путь
  вызывает `rewriteSNAT` без полноценного NAPT. Продолжить тесты изоляции клиентов.
- Android: перенести чувствительные настройки из обычных SharedPreferences
  в защищённое хранилище.
- iOS: подписать IPA с NetworkExtension entitlement и провести тесты на устройстве.
  Успешная сборка и проверка типов не подтверждают работу VPN на iPhone.
- Пересверить весь исторический реестр ревью с текущим кодом: его верхняя сводка
  отложенных задач устарела, а ✅/🟡 в таблицах означают уверенность исходной
  находки, а не достоверный текущий статус исправления.
