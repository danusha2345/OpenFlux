# Исключения из VPN в Desktop 3.7.2

Настройки → VPN → «Исключения из VPN». Правила работают в режиме
«Весь трафик компьютера (TUN)» и применяются при следующем подключении.
Профиль нашего сервера менять или импортировать заново не требуется.
Серверу эти правила не передаются; его прошлая конфигурация совместима.

## Настройка

- **Приложения вне VPN (Windows).** Нажмите «Добавить приложение (.exe)» и
  выберите исполняемый файл любой программы, в том числе любого торрент-клиента.
  Правило относится к выбранному executable, а не к портам или сигнатуре
  BitTorrent. TCP и UDP IPv4 этой программы открываются через исходный
  сетевой интерфейс. Дочерний процесс с другим executable добавляется отдельно.
- **Локальная сеть (Windows/Linux).** Разрешает RFC1918 IPv4, link-local,
  локальный multicast/broadcast и локальные IPv6 ULA/link-local адреса.
  Существующие маршруты к подключённым подсетям сохраняются. Для имён
  `.local`, `.lan`, `.home` и однокомпонентных LAN-имён на Windows используется
  DNS физического адаптера; домен внутренней организации можно добавить
  в список сайтов. На Linux resolver прямых соединений использует 1.1.1.1;
  для внутренних имён предпочтителен доступ по LAN IP.
- **Сайты вне VPN.** По одному домену на строке, без протокола и URL-пути.
  Поддомены включаются: `example.com` охватывает `www.example.com`,
  но не `notexample.com` и не `example.com.other`. Поддерживается IDN.
  Сторонние домены CDN/API сайта при необходимости добавляются отдельно.

После добавления доменов перезапустите браузер для сброса его собственного
DNS-кэша. Для доменных правил отключите защищённый DNS/DoH в браузере:
имя, разрешённое внутри зашифрованного DNS-соединения, клиенту не видно.
Правила приложений от DoH не зависят. Собственный SOCKS/HTTP-прокси в
торрент-клиенте следует отключить, если ожидается прямое соединение.

## Реализация и границы

Когда исключений нет, сохранён прежний прямой packet-forwarding TUN.
При включённых исключениях используется локальный gVisor packet proxy;
DNS A для имён получает синтетические адреса 198.18.0.0/16. Исходное имя
сохраняется до выбора direct/VPN dialer, поэтому общий CDN IP не открывает
обход другим доменам. Локальные DNS-записи и специальные записи (SRV/TXT/PTR)
передаются нужному resolver. Остальные имена разрешаются через exit при dial.
IPv4 TCP/UDP выбранных приложений проксируются напрямую сокетами ядра,
привязанными через netbind. Публичный IPv6 остаётся заблокированным, как
и до этого выпуска; исключение приложений не включает публичный IPv6.
Входящие публичные порты torrent-клиента автоматически не открываются.
При нескольких VPN «напрямую» означает через интерфейс, выбранный до OpenFlux.

Windows определяет executable по полному исходному IPv4 socket tuple через
GetExtendedTcpTable/GetExtendedUdpTable и QueryFullProcessImageName.
Неизвестный/неоднозначный владелец остаётся в VPN. В частности, UDP port sharing
между разными процессами не расширяет исключение на посторонний процесс.
WFP продолжает блокировать обход прочих приложений; для LAN добавляются
только перечисленные локальные префиксы. DNS block и dynamic WFP cleanup
сохранены. Linux использует прежнюю отдельную nftables table с локальными
исключениями перед IPv6 reject; чужие firewall-правила не изменяются.

Windows socket API и layout сверены с первичными источниками:
[GetExtendedTcpTable](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedtcptable),
[MIB_TCPROW_OWNER_PID](https://learn.microsoft.com/en-us/windows/win32/api/tcpmib/ns-tcpmib-mib_tcprow_owner_pid),
[MIB_UDPROW_OWNER_PID](https://learn.microsoft.com/en-us/windows/win32/api/udpmib/ns-udpmib-mib_udprow_owner_pid).

## Проверка

Добавлены тесты границ доменов/путей/подсетей, byte order и неоднозначных UDP
owner tables, TCP/UDP DNS, локального DNS, сохранения настроек и передачи
аргументов ядру. Пакетный тест прогоняет IPv4 через тот же SplitTransport,
что использует TUN: исключённый сайт и произвольный torrent executable идут
через direct dialer, обычный TCP-поток проходит через отдельную exit-ноду.
Тест не меняет маршруты компьютера.

Windows amd64/arm64 кросс-сборки и 386/amd64 test executables проверяют
компиляцию. В `routing/owner_windows_test.go` есть нативный тест собственного
TCP/UDP PID, который следует запускать на Windows; Linux его не выполняет.
Это не физическая проверка WFP/Wintun и выбранного торрент-клиента на Windows.

Итог локальных проверок: Go `test -race ./...` и `vet ./...` прошли в core;
mobile race/vet прошли. Shared JVM: 678 tests, Desktop: 9 tests, без ошибок.
`govulncheck` не находит уязвимостей импортируемых пакетов. Ветку Windows
owner lookup проверяют таблицы-fixtures на Linux и отдельные Windows tests,
а не утверждение о выполненной физической проверке на Windows.
