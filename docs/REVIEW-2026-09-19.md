# Повторное ревью и исправления — 19.09.2026

Проверены пути Yandex Docs и Volga, остановка L3, а также наличие ранее
заявленных исправлений в iOS и хранение настроек Android. Это не подтверждение
закрытия всего исторического реестра от 17.09.2026.

## Исправлено в текущем рабочем дереве

### Volga

- HTTP relay при 401/403 обновляет авторизацию и один раз повторяет батч.
  Конкурентные отказы одного успешно заменённого токена используют одно обновление.
  После повторного отказа возвращается ошибка, бесконечного retry нет.
  Неудачная авторизация включает общий backoff 1–30 с против лавины запросов.
- Пул сокращён с 2000 до 8 workers, HTTP idle pool — до 16 соединений
  (8 на хост). Пиковую скорость и порядок параллельных POST ещё нужно измерять.
- HTTP-запрос получает отдельный снимок настроек клиента с CookieJar своей
  авторизации. Устранена запись в общий `http.Client.Jar` во время `Do`,
  убрано дублирование Cookie при наличии Jar.
- HTTP и WS используют одну актуальную авторизацию. Обновление закрывает старый
  WS; проверка после dial не позволяет опубликовать соединение со старым токеном.
- Авторизация принимает context; HTTP-запросы отменяются при остановке refresh,
  начальная авторизация ограничена 60 секундами. Относительные redirect URL
  разрешаются через `ResolveReference`, ошибки создания запроса проверяются.
- Stop закрывает WS и ждёт reader/фоновые циклы; повторный Stop безопасен,
  канал фоновых циклов пересоздаётся на Start. Повторный Start запущенного
  транспорта отвергается, ошибка первоначальной авторизации снимает running.
- Send после завершённого Stop отвергается. Stop не держит блокировку,
  необходимую callback при отправке ответа, пока ждёт WS reader.
- Длина пакета проверяется против uint16 независимо от настроек. Повреждённый
  батч отбрасывается целиком вместо передачи усечённого payload как IP-пакета.

### Yandex Docs

- Read deadline после OPEN больше не снимается: используется сумма
  `pingInterval + pingTimeout`, при отсутствующих/некорректных значениях — 45 с.
  Deadline продлевается при входящем кадре. Некорректный OPEN вызывает reconnect.
- Запись ограничена 15 секундами; ошибка writer закрывает сокет и будит reader.
  Во время disconnected writer удерживает пакет до восстановления.
- Engine.IO close и Socket.IO disconnect/connect_error закрывают сокет.
- Отмена context закрывает WS даже во время ожидания первого OPEN.

### L3

- Цикл статистики завершается по остановке conntrack.
- Send/Recvfrom синхронизированы с закрытием raw-дескрипторов; Send после
  закрытия возвращает `net.ErrClosed`. Receive timeout 250 мс ограничивает
  ожидание текущего Recvfrom перед освобождением fd.

## Остаток — не считать закрытым

1. **Volga:** длительный тест истечения настоящего токена и превентивное
   обновление по TTL. Порядок параллельных POST не гарантирован;
   нужна проверка производительности ограниченного пула.
   Ожидание Stop при первоначальном Start исправлено в продолжении ниже.
2. **Yandex Docs:** транспорт выставляет connected до auth-ack; внешняя Noise
   обёртка смягчает это для приложения, но не исправляет состояние самого carrier.
   Остаются полный разбор auth-fail и проверка нового пути редактора.
3. **L3:** полноценный NAPT, коллизии с потоками хоста, изоляция нескольких
   клиентов, PMTU/ICMP и UDP. Новые изменения закрытия raw-сокета требуют также
   live-проверки с CAP_NET_RAW; проведённый HTTPS использовал L4.
4. **iOS:** Keychain не реализован: URL/MAX token остаются в AppStorage и
   providerConfiguration. Выбор профиля и сериализация load/start исправлены в продолжении ниже,
   но Swift-правки ещё требуют проверки с Apple SDK.
   Нужны подписанная сборка и тест на устройстве, включая сон/смену сети.
5. **Android:** конфигурации остаются JSON в обычных SharedPreferences;
   требуется защищённое хранилище с миграцией. Длительное восстановление и
   точность счётчиков требуют проверки на телефоне.
6. **Прочие транспорты/macOS:** остаток старого реестра требует отдельной
   сверки с исходниками и воспроизводимых тестов; текущий проход его не закрывает.

## Исправление формулировок старого ревью

Значки ✅/🟡 в старой таблице означали уверенность находки, а не состояние
исправления. Верхняя сводка местами противоречит коду: например, on-demand на
iOS уже включён, а Keychain отсутствует. Нельзя выводить число оставшихся
багов подсчётом значков.

Публичный Peer key подтверждает сервер, но не ограничивает круг клиентов.
Без PSK любой, кто знает публичный ключ и документ, может попытаться подключиться.
Наличие Noise само по себе не закрывает изоляцию клиентов или NAPT.

## Продолжение после коммита 0c22f72f

Первый набор исправлений сохранён коммитом
`0c22f72fca5c858d34d416df9950caaaa9a38180`.
Следующие изменения находятся в отдельной рабочей change:

- Volga Stop отменяет первоначальную авторизацию, а не ждёт её 60-секундного
  таймаута. Start не публикует транспорт после отмены. Проверено локальным
  HTTP-сервером с заблокированным ответом и `go test -race`.
- BaseTransport синхронизирует время старта с Stats. Новый конкурентный тест
  воспроизводит DATA RACE на коде предыдущего коммита (через Go overlay)
  и проходит после исправления.
- iOS VPNController выбирает только профиль с bundle ID своего расширения;
  ошибка чтения preferences не интерпретируется как отсутствие профиля.
  Начальная загрузка разделяется между вызовами; повторные нажатия Start
  блокируются, Stop во время подготовки отменяет запуск. При остановке
  ошибка сохранения on-demand больше не скрывается.
- События NetworkExtension во время операции не снимают состояние подготовки;
  после операции статус перечитывается. Поздний результат старой загрузки
  не стирает уже выбранный профиль или новую задачу загрузки.

Проверки продолжения: `go test -race ./...`, `go vet ./...`, проверка Go-мостов
`scripts/ios-typecheck.sh`. Они не компилируют Swift: изменение VPNController
требует сборки с Apple SDK и тестов Start/Stop на устройстве. Mac/Swift toolchain
в текущем окружении отсутствует. Keychain, NAPT и прочий ранее перечисленный
остаток этим продолжением не закрыты. Push и обновление постоянных служб
на этом этапе не выполнялись.
